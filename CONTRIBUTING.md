# Contribuindo para o Sangris Interface

Obrigado por considersar contribuir para o projeto! 🎉

## 🚀 Como Contribuir

### 🐛 Reportando Bugs

1. Verifique se o bug já foi reportado nas [Issues](https://github.com/duugagno/sangris-vrising-mod/issues)
2. Se não encontrou, [crie uma nova issue](https://github.com/duugagno/sangris-vrising-mod/issues/new)
3. Inclua:
   - Descrição detalhada do problema
   - Passos para reproduzir
   - Versão do mod e do V Rising
   - Logs (se disponíveis)

### 💡 Sugerindo Melhorias

1. [Abra uma feature request](https://github.com/duugagno/sangris-vrising-mod/issues/new)
2. Descreva:
   - A funcionalidade desejada
   - Por que seria útil
   - Como deveria funcionar

### 🔧 Contribuindo com Código

1. **Fork** o repositório
2. **Clone** seu fork:
   ```bash
   git clone https://github.com/SEU_USUARIO/sangris-vrising-mod.git
   ```
3. **Crie** uma branch para sua feature:
   ```bash
   git checkout -b feature/nova-funcionalidade
   ```
4. **Faça** suas alterações
5. **Teste** suas mudanças
6. **Commit** suas alterações:
   ```bash
   git commit -m "feat: adiciona nova funcionalidade"
   ```
7. **Push** para sua branch:
   ```bash
   git push origin feature/nova-funcionalidade
   ```
8. **Abra** um Pull Request

## 📝 Padrões de Código

### Commits
Use o padrão [Conventional Commits](https://www.conventionalcommits.org/):

- `feat:` - Nova funcionalidade
- `fix:` - Correção de bug
- `docs:` - Mudanças na documentação
- `style:` - Formatação, etc.
- `refactor:` - Refatoração de código
- `test:` - Adição de testes
- `chore:` - Tarefas de manutenção

### Pull Requests
- Título claro e descritivo
- Descrição detalhada das mudanças
- Referência às issues relacionadas
- Testes realizados

## 🔧 Desenvolvimento Local

### Pré-requisitos
- V Rising instalado
- BepInEx 5.0+
- Visual Studio ou equivalente
- Git

### Setup
1. Clone o repositório
2. Abra no Visual Studio
3. Configure o path do V Rising
4. Compile e teste

## 📋 Checklist para PRs

- [ ] Código compila sem erros
- [ ] Funcionalidade testada no jogo
- [ ] Documentação atualizada (se necessário)
- [ ] CHANGELOG.md atualizado
- [ ] Commits seguem o padrão
- [ ] PR tem título descritivo
